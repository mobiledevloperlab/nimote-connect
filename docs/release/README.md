# 发布维护指南

[公开仓库首页](../../README.md)

在私有开发环境构建、验收并审计商业包，在本仓库对应的 **GitHub Releases** 分发安装归档与校验文件。公开仓库的 Git 标签指向本仓库的文档提交。

## 文档目录

- 根目录 `README.md` 是英文产品首页，也是 GitHub 默认入口。
- `docs/{zh,es,ja,ko}/README.md` 分别是简体中文、西班牙语、日语和韩语产品首页。
- `docs/{en,zh,es,ja,ko}/install.md` 是对应语言的安装与连接指南。
- `docs/release/README.md` 是本发布维护指南。

更新产品能力、安装命令或平台验收状态时，同步修改受影响的语言版本，并检查语言切换链接是否指向同类型页面。

## 发布前

1. 核对目标版本的平台、架构、客户端兼容性、连接方式和升级路径。发布说明按实际验收结果标注范围。候选版本如获准公开，标为预发行版，写明已知限制。
2. 在私有环境使用已有的发布审计检查每个最终归档。核对完整文件清单、版本、目标平台、两项程序、安装入口、公开使用说明、许可证及声明。与安装包一起分发的安装脚本属于交付文件。归档只保留安装和运行所需的对外文件，排除产品源码、私有构建脚本、调试符号、内部文档和凭据。
3. 用最终安装包生成并复核同名 `.sha256`。保留制品中的第三方许可证和版权声明。仅在对实际上传的文件完成签名及核验后，才在发布说明中标注已签名。
4. 检查准备公开的提交和标签中可达的 Git 历史，确认只包含公开资料，并检查发布附件清单。`release/` 中提交的安装包会进入公开 Git 历史。

## 创建版本

1. 将验收后的归档与同名 `.sha256` 放进仓库根目录的 `release/`。CLI 归档使用 `nimote-connect-<版本>-<系统>-<架构>.tar.gz`（Windows 使用 `.zip`）。桌面归档使用 `nimote-connect-commercial-` 前缀。系统字段分别为 `darwin`、`linux` 和 `windows`，架构字段为 `amd64` 或 `arm64`。
2. 可在同一提交中添加 `release/v<版本>.md`，供工作流创建 Release 时使用。
3. 提交后推送到 `master`。Actions 会验证商业版本归档的 SHA-256，创建对应的 `v<版本>` 标签，并上传归档与校验文件。当前正式版使用 `1.2.1`，标题为 `Nimote Connect 1.2.1`，标签为 `v1.2.1`。Beta 和 RC 使用 `1.2.0-beta.1`、`1.2.0-rc.1` 这样的版本号，标记为 Pre-release。`local`、`ci` 和 `dev` 构建会跳过公开发布。
4. 补传平台或更新归档时，将对应文件和校验值一起推送到 `master`。工作流会更新同一 Release 中新增或变动的附件。也可在 Actions 中手动运行 **Publish release packages** 来重试。已启用不可变发布的版本需要使用新版本号更新附件。

GitHub 自动生成的 `Source code` 下载来自标签指向的仓库快照，其中包含已提交的安装包。用户可从 Release 的 **Assets** 直接下载所需平台的归档。

每个版本写明以下信息，便于用户下载和升级。

- **版本与渠道**。版本号、发布日期以及正式版或预发行版。
- **变更与适用范围**。新功能、修复项、支持的系统和架构、客户端兼容要求。
- **安装与升级**。安装入口、账户及 OpenSSH 要求、升级前需要完成的活动任务，以及适用的回滚方法。
- **附件与验收**。归档及匹配的校验文件、已完成的验收、已知限制。
